# Extension environments & build

Two environments control which POS/API the extension talks to:

| Env | POS URL | Chat API |
| --- | ------- | -------- |
| **local** | `http://localhost:8000/` | `http://localhost:8000/api/chat/...` |
| **live** | [https://testv3.websitedemolynk.com/pos/](https://testv3.websitedemolynk.com/pos/) | `https://testv3.websitedemolynk.com/pos_admin/api/chat/...` |

Config files:

- `env/local.js` — local definitions
- `env/live.js` — live definitions
- `env.js` — **active** env for unpacked development (copied by switch/build)

## Switch env (unpacked / Load unpacked from repo)

```bash
npm run env:local
npm run env:live
```

Then reload the extension in `chrome://extensions`.

## Local/Live API toggle (local only)

Local builds and `npm run env:local` also embed the live config in `env.js`
(`WA_ENV.alternates.live`, generated by `scripts/env-source.js`). That shows a
**Local | Live** toggle in the sidebar header, so a local build can talk to the
live POS APIs without rebuilding. Live/store builds don't embed it, so the toggle
never appears there.

- The choice is saved in `chrome.storage.local` (`wa_env_override`) and used by
  the sidebar, popup and background.
- Switching stops any send in progress, clears the saved API URLs and rebuilds
  the sidebar; log in to that env's POS (and keep the tab open) as usual.
- Local builds get both POS hosts in `host_permissions` and `posBridge.js` matches.

## Create builds

```bash
npm install
npm run build:local   # → build/store-sync-whatsapp-sender-v{version}-local/
npm run build:live    # → build/store-sync-whatsapp-sender-v{version}-live/
npm run build:all     # both
npm run build         # alias for live
```

Every package file is processed:

| File | Treatment |
|------|-----------|
| `env.js` | Minified only (chosen env) |
| `content.js` | Minified (+ obfuscated in local builds only) |
| `background.js` | Minified (+ obfuscated in local builds only) |
| `posAuth.js` | Minified (+ obfuscated in local builds only) |
| `popup.js` | Minified (+ obfuscated in local builds only) |
| `posBridge.js` | Minified only |
| `posInject.js` | Minified only |
| `sidebar.css` | Minified |
| `popup.html` | Minified |
| `manifest.json` | Minified JSON (POS `content_scripts` matches and `host_permissions` limited to WhatsApp Web + that env's POS host; local builds add the live host for the API toggle) |
| `INSTALL.txt` | Env-specific install steps |

Live builds are never obfuscated: the Chrome Web Store rejects obfuscated code.
`localSocket.js` (dev `ws://localhost:3000` Start trigger) is packed only in local builds.
Live builds also write `build/store-sync-whatsapp-sender-v{version}-live-store.zip`
(manifest at the zip root, no `INSTALL.txt`) — upload that file to the Chrome Web Store.
Privacy policy for the store listing: [privacy-policy.html](privacy-policy.html) (host it on the POS domain).

## Friend install (live example)

1. Load unpacked `build/store-sync-whatsapp-sender-v*-live/`.
2. Open/login [https://testv3.websitedemolynk.com/pos](https://testv3.websitedemolynk.com/pos/) and **refresh that tab**.
3. Open the extension popup — should show **Welcome …**.
4. Open WhatsApp Web and use the sidebar.

## Friend install (local example)

1. Load unpacked `build/store-sync-whatsapp-sender-v*-local/`.
2. Open/login `http://localhost:8000/` and refresh that tab.
3. Open WhatsApp Web and use the sidebar.

## Limits

Obfuscation makes reading harder; it does not make code uncopyable.
